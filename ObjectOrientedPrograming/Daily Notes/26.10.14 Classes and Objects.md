# Classes are made up from _State_ and __Behaviour__
They are the blueprint / template. They can also be thought of as and _abstract datatype_.

# Object
An instance of the class with its own place in memory.

# Syntax
In java we use _camelCase_
Every property or method is marked __private__ unless it ablsolutely needs to be _public_. ( Minimal privilege rule )

Example Code we did in class :
```Java
// 1. Define the class.
public class Account {
	
	// 2. Define its propperties.
	private String accountNumber;
	private String ownerName;
	private double balance;
	
	// 3. Define the constucor/s.
	public Account( String accNum , String name , double balance ) {
		
		// The `this.` syntax is used to reffer to the class properties.
		// Here the `this.` syntax is optional but is good practice to use because it helps identify the intent of the code.
		this.accountNumber = accNum;
		this.ownerName = name;
		this.balance = balance;
		
	}
	
	// 4. Define the getters and setters.
	// We can safely make getters for every property.
	// We must only make setters for properties we absolutely want to be changed directly by other classes.
	
	// Geters have the same type as the property they are getting and no parameters.
	public String getAccountNumber(){
		return this.accountNumber;
	}
	
	public String getOwnerName(){
		return this.ownerName;
	}
	
	public double getBalance(){
		return this.balance;
	}
	
	// For this class we will have no setters because we do not want our properties to be modified by other classes.
	
	// 5. Define the class methods 
	public boolean deposit( double ammount ){
		
		if ( ammount < 0 ) {
			return false;
		}
		
		balance += ammount;
		return true;
		
	}
	
	public boolean withdraw( double ammount ){
		
		if ( ammount < 0 || ammount > balance ){
			return false;
		}
		
		balance -= ammount;
		
	}
	
	
	// Classes in Java come with built in methods, one of which is `toString()`. this method is used when we try to print out a class the the terminal and it returns a string describing the class.
	
	// We can overide this method and make it return a more personalized string. We can mark this method with the @Overdie decorator which informs the compiler we are trying to overide an existing method. With this knowlege the comiler can warn us if we misspell the method name or mix up the return type.
	
	@Overide
	public String toString(){
		return "{ AccountNumber: " + this.accountNumber + ", OwnerName: " + this.ownerName + ", Balance: " + balance + " }";
	}
	
}
```

Then we made the main program:
```Java

public class BankApp {
	
	// the `static` keyword tells the compiler to never make copies of this method but to always use the same place in memory and just refer back to it.
	public static void main( String[] args ){
		
		Account ada = new Account("AC-1001", "Ada Lovelace", 500.00);
		System.out.println(ada);
		
		if (ada.withdraw(200.00)) {
			System.out.println("Withdrawal accepted.");
		} else {
			System.out.println("Not enough money.");
		}
		
		if (ada.withdraw(900.00)) {
			System.out.println("Withdrawal accepted.");
		} else {
			System.out.println("Not enough money.");
		}
		
		System.out.println(ada);
		
	}
	
}

```

The output should be :
```
{ AccountNumber: AC-1001, OwnerName: Ada Lovelace, Balance: 500.00 }
Withdrawal accepted.
Not enough money.
{ AccountNumber: AC-1001, OwnerName: Ada Lovelace, Balance: 300.00 }
```
