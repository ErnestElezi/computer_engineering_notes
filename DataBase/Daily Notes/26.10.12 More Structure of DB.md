# Entity Integrity
To keep entity integrity we must avoid key attributes being set to null.

# Referential Integrity
Foreign keys in a _relationship_ must be valid keys in a relation somewhere.

# Update Effects
## 1. Restrict
Don't allow record deletion if any reference to it exists. Must delete all foreign keys leading to a record before you're allowed to delete the record.
## 2.  Cascade
When deleting a record also delete all records that hold its foreign key. __Very dangerous if the DB is not configured properly.__
## 3.  Set _NULL_
When deleting a record set all its foreign keys on the DB to NULL. _Only works out if DB design is compatible._
## 4.  No action
When deleting a record do nothing about all the foreign keys that now point to nowhere.

# Default Values
When we define attributes _( columns )_ for relations we can define some default values to be added if the field was left __NULL__.
Very useful when we want to avoid __NULL__ properties.

# Theroretical Syntax
Relations are makred with __$\large R$__:
A relation with a few attributes can be written as:
$$
\large R(\ A_1,\ A_2,\ A_3,\ ...\ , A_n\ )
$$

A super key can be written as :
$$
\large SK = \big\{\ A_1,\ A_2,\ A_3,\ ...\ , A_m\ \big\}
$$

And to properly say that: _"Two Super Keys cannot be the same for different Records"_
$$
For\ every\ \{ t_1\ , \ t_2\} \in R 
$$
$$
t_1[SK] \neq  t_2[SK]
$$
