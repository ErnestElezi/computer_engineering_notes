SQL - Structured Query Language, not really a programming language but more of a _Formal Language_ to talk to a program so we can do what we need. __SQL on its own is not Turing Complete__

A _statement_ is a instruction for the program. Instrucitons run one after the other and are split by `;`.

Parts of SQL:
- DDl - Data Definition Language - Defines the structure
- DML - Data Modeling Language

# Using SQL
The subject uses MySQL Workbench and Server. We can use HeidiSQL and MariaDB cause they're better with linux.

We will be using the word _schema_ to describe one system, because a database can have many systems running on the same server independently.
## Creating a new schema
```SQL
create schema 'university';
```
__SQL does not care about capitalization unless it is inside quotes.__

The above statement will create a new schema named `university` on our database.
We will go deeper into the `create` syntax later. For now we will create _schemas_ and  _tables_ using it.

## Creating a table
```SQL
create table 'university'.'department';
```
The above code specifies to create a new table called `department` inside the `university` schema.
Because it can be annoying to always specify the schema in every _statement_, we can just use the `use` syntax.
```SQL
use 'university';
create table 'department';
```
All _instructions_ under the `use` syntax will refer to the `university` schema.

__If we try to execute this instruction we will get an error that says : Tables must have at least one attribute!__

## Creating a table with attributes
```SQL
use 'university';
create table 'department'(
	name varchar(20),
	id tinyint,
);
```
Now we have defined _attributes_ of different types to our table.
In SQL we define attributes with the syntax `<name> <type>,`. Opposite of most programming languages.
The first attribute is a string of 20 characters and the second is a `8-bit` integer, because we don't expect to have more than 255 departments.
Bot the attributes are passed in as _input_ to the table and are a part of a single statement (notice the single semi-colon at the end), even though the statement is spread across 4 lines.
To the compiler it will still look like this:
```SQL
use 'university';
create table 'department'(name varchar(20),id tinyint);
```

__P.s. We want to always pick the smallest datatype for our attributes to save storage space because our database can hold milions of records.__

## Attribute Constraints
- _not null_ -> Forces the attribute to have a value
- _unique_ -> Forces the attribute value to be unique from all other records
- _primary key_ -> Both unique and not null and is also used to query records so we must pick the simplest identifying attribute to save computation time.
- _default_ -> Adds a fallback value to stop null values getting through
- _foreign key_ -> Attribute must be a valid foreign key to another record in another __relation__ _(aka table)_.
- _auto\_increment_ -> Will automatically give a value form an internal incrementing counter that we can set the starting value to.

## Deleting tables/schemas
```SQL

drop schema '<schema_name>';
```
__Very dangerous, Will nuke everything permanently!__
