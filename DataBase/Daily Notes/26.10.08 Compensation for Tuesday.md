# The Relational Data Model
This model applies constraints to force organised _data_.

## Entity and Relationship _[[DataBase/Definitions#ER Schema|(ER)]]_

### [[DataBase/Definitions#Entities|Entity]]
Is defined by attributes, which are usually simple values.
This element is schematically drawn as a rectangle with the name of the _Entity_ written in the middle.

![[Entity.svg]]

### [[DataBase/Definitions#Relationships|Relationship]]
Is defined by the Entities it connects and its own properties.
This element is schematically drawn as a diamond with the name of the _Relationship_ written in the middle.

![[Relation.svg]]

One _Entity_ can have more than one Relationship.
__Entities are also allowed to have Relationships to themselves!__

## [[DataBase/Definitions#Properties|Properties]]
These represent attributes that define _Entities_ and _Relationships_.
They are schematically drawn as a Circle/Oval with the name of the property written inside.

![[Properties.svg]]

## [[DataBase/Definitions#Key|Keys]]
They are the property that _uniquely_ identify a [[DataBase/Definitions#Record|Record]] in the database.
Schematically they are drawn the same as other properties but with and underscore.

![[KeyProperty.svg]]


## Types of Properties:
### - Simple
Just a number / date / character / string.
### - Composite
Not really explained yet.
### - Multi-valued __( Very frowned upon )__
Storing multiple strings inside one string.
E.g. storing all the programming languages a employee knows as a single string like `"C,C++,C#,Rust,Java,JavaScript"`.

## The [[DataBase/Definitions#NULL|NULL]] value:
_Null_ in the context of Data Bases means lack of information.
A value marked _Null_ is either Unknown, Unavailable or Inapplicable.
You can not query for a _Null_ value

## [[DataBase/Definitions#Cardinality|Cardinality]]
It represents the number of times an _Entity_ be referenced by others.
_Entities_ can reference:
- One-to-One   __[1..1]__
- One-to-Many  __[1..N]__
- Many-to-One  __[N..1]__
- Many-to-Many __[N..N]__

### Constraints __(AKA Limits on Cardinality)__
We can constrain how many times _Entities_ relate to one-another.
We can specify minimum, maximum or both number of relations for a [[DataBase/Definitions#Record|Record]] to be valid. `[0..1]` , `[1..N]`  ect.
The constraint `[0..N]` is usually written as `*`.
